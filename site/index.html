Sense a room with the WiFi you already have.

One ESP32 or one Raspberry Pi joins your network, pings the access point 100 times a second, and measures what the room does to each reply. Motion, presence and breathing rate, computed on your own hardware and stored on your own disk.

Node → air → server → you

One node makes its own traffic, then measures it

Channel State Information is what a WiFi radio already computes to decode a packet: a complex amplitude and phase for every subcarrier. A person in the path changes it. That is the whole physical basis — no camera, no microphone, no wearable.

The catch is sample rate. A station that only listens gets a CSI callback whenever the access point happens to address it, which on an idle network is a few frames a second. The spectrum you compute from that describes your household's traffic pattern, not your room.

So the node provokes its own downlink stream. It sends a probe at a fixed 100 Hz and reports CSI for every reply, which makes the sampling rate a property of the node rather than of the network. The link it senses runs from the node to the access point — pick which access point, and you have picked the line through the house the system watches.

The probe is a UDP round trip through the server, because routers rate-limit ICMP: this one stopped answering pings entirely under sustained probing while still answering a laptop, and the yield went from 0% to 96% on the switch.

Pick one

Two kinds of node, one uplink format

They are interchangeable by design. Nothing in the recorder, the DSP or the web app knows which one it is looking at.

Option A

ESP32-S3 or ESP32

One board, flashed once, then configured from a settings page it serves itself — SSID, BSSID lock, server address and probe rate, no toolchain and no cable. Timestamps are taken in the CSI callback, which is as close to the antenna as this gets.

Option B

Raspberry Pi + nexmon_csi

A Pi 3B+, 4, 5 or CM4 patched to report CSI while it listens, so the same box can be sensor, server and UI at once. Four times the frequency resolution, paid for in kernel-level timestamps, per-frame amplitude scaling, and a wired uplink — the CSI firmware costs the radio its own data connection.

What you get

An instrument first, a detector second

The waterfall is the view you use to decide whether the capture chain works at all: wave an arm, and if it does not visibly react, nothing downstream is worth reading. Everything else — motion, presence, breathing, heart rate, placement — is computed server-side, identically for live and replayed frames, so a recording is a faithful stand-in for the room.

Before you build one

What it will and won't do

Single-link, amplitude-only sensing is one scalar view of a room. That buys a surprising amount and it has a hard ceiling, and knowing where the ceiling is up front is worth more than an optimistic feature list.

Will
  • Motion detection
  • Room-level presence
  • Breathing rate at tuned positions
  • An overnight activity record
  • A genuinely nice CSI visualization tool
Won't
  • Localization or direction
  • Reliable multi-person counting
  • Pose
  • Heart rate beyond close range, motionless
  • CSI-ratio tricks — two boards, two oscillators
Start here

Try it without any hardware

The stack ships with a synthetic node whose channel model is physical enough that the answers are known — a specific breathing rate, a specific motion schedule. It is how the DSP was developed and how it is tested, and it is the fastest way to see whether the app is worth putting a radio behind.
